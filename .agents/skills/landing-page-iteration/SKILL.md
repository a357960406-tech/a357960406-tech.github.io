# 落地页设计与迭代

目标：将需求变成能在浏览器中检查的页面，在多轮修改中保住已确认的设计与交互。参考站提供具体布局和行为证据，产品内容、品牌与素材按用户要求确定。

## 进入任务

- **新建页面**：先确认影响整体方向的缺口，例如产品定位、页面范围、主要内容、目标设备、参考点与交付形式。用户要求多轮澄清时先对齐方案；用户随后明确要求“先做可预览页面”或“开始做”，按新的授权推进。
- **现有页面修改**：从最新有效入口和当前浏览器状态开始，读取实际引用的样式、脚本及已有改动。不要重新设计整站，也不要恢复被取消的内容。
- **仅复盘或创建 Skill**：交付经验与技能文件，不修改网站，不触发发布。
- **发布**：只在对应授权范围内执行，阅读 [发布与线上验证](references/github-pages.md)。预览授权不等于公网发布授权。

## 把要求变成可核对的改动

维护简短工作记录，字段按任务缩减：当前版本、入口、品牌与文案、区块顺序、目标设备、保留项、本轮修改、待确认项、预览地址、发布状态。

以稳定区块名或 DOM id 识别页面，例如 Hero、互动区、精选作品、沉浸大图、结尾。新增、删除或 sticky 动画会改变“第几屏”的含义，先映射到具体区块。能从上下文确定时直接做，确实会删错内容时才问一个有针对性的问题。

将模糊反馈落实为观察结果：

- “间距减半”：调整卡片实际边缘间距，不仅是容器 padding。
- “文字往中间移动”：确认视觉中心及锚定容器，避免只改在另一视口失效的像素值。
- “图片环绕”：区分整体弧形遮罩、独立卡片曲面与透视排列，按要求改变图片本身或空间结构。
- “前后景 / 近远运动”：确认先拉近还是先拉远、随后是否俯视，不能交换动画顺序。
- “其他保持不变”：只调整对应参数和必要依赖，验证相邻区块与原有交互。

最新明确修改覆盖旧的冲突要求，未冲突约束继续生效。单次偏好不自动升级为所有未来项目的通用规则。

## 参考分析与首版

浏览指定参考页面，检查用户点名的区块与状态：稳定布局、悬停前后、滚动起止、跨区块转场。把参考点写成可实现的行为：触发方式、方向、层级、图片裁切与终止状态。不能访问或未观察到时说明证据缺口，不声称完全一致。

首版优先实现决定方向的布局、素材、文字比例和主要交互，直接提供可预览页面。用户只要预览时，不先制作冗长原型说明。沿用适合项目的技术栈，静态页面不因视觉效果复杂就默认引入整套框架。

素材质量、动效实现与检查按需阅读 [素材与动效](references/visual-motion.md)。

## 持续迭代

1. 确认最新入口和变更范围，用 Git 或现有快照保留可恢复基线。
2. 修改最小相关范围，尽量让布局、悬停、滚动与图片内部运动控制不同层或独立变量。
3. 卡片数量、筛选或区块尺寸改变时，同步重算滚动长度、终点、翻转时机和锚点。
4. 验证本轮改变及直接受影响的交互。视觉与滚动改动要在浏览器观察，代码检查不能替代实际预览。
5. 更新真实预览地址与必要工作记录。用查询参数刷新缓存时，确认入口确实引用新文件；参数本身不会更新代码。

不要持续叠加旧样式覆盖、多个 scroll 控制器或重复监听。历史版本形成很长的 CSS import 链时，后续整理应先保留可回退快照，再减少串行加载；局部修改不顺便进行大规模重构。

继续当前项目时，阅读 [本项目案例](references/project-retrospective.md)，并以实际文件和最新要求为准。

## 验证与交付

检查与本轮相关的桌面视口、悬停边缘和中心、滚动中间态与最终态。重点验证素材清晰度与主体裁切、层级穿模、筛选空态与单卡、终点翻转、弹窗关闭/收藏/下载、导航落点、运行错误。低风险且没有改变的区域不反复跑全套测试。

用户只要求桌面端时按桌面验证，不把移动适配作为额外完成条件。保留合理的减少动态效果与失效降级，不影响主要体验。

交付先说结果：本轮改动、可点击预览链接、实际验证情况与影响使用的限制。未启动预览或未成功部署时，不把本地文件或预计网址说成已可访问。需要用户操作时，指出具体卡点与最短操作路径。
