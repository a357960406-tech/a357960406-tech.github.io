01 / WHAT IT DOES

把制作过程，
变成一套有章法的协作。

它不是网页模板，也不绑定某一种风格。
它为 Codex 提供制作、修改和验收页面的方法。

01

需求与上下文

先确认产品、区块、设备与参考点。持续记录保留项和本轮改动，用稳定区块名称定位，避免“第几屏”变化后改错地方。

对齐方向
02

参考分析与可预览首版

观察参考站的实际布局、悬停和滚动状态，再转化成符合产品的页面。需要预览时直接制作可运行页面，不停留在冗长方案。

看得见的结果
03

素材与动效调试

检查高清图片、主体裁切与最大放大状态。将环绕、倾斜、拖尾、翻转和景深分层控制，排查穿模、抖动与露边。

细节到位
04

局部迭代与回归验证

让“其他保持不变”成为具体约束。数量、筛选和尺寸变化时，同步检查滚动长度、翻转时机、弹窗与下载。

保住已确认的体验
05

提交与发布确认

在你明确要求后处理 Git 提交、GitHub 同步与 Pages 发布。区分上传成功和部署成功，打开正式网址验证资源与交互。

02 / THE COMPLETE WORKFLOW

从想法到上线，
每一步都有明确结果。

新项目从需求开始，已有页面从当前版本开始。
每轮围绕具体改动推进，确认效果后再进入下一步。

  1. 01 / ALIGN

    对齐需求与边界

    说明产品是什么、面向谁、希望访客做什么。确认单页范围、设备、文案素材、视觉方向，以及需要保留或取消的内容。

    这一步交付需求摘要 · 区块顺序 · 保留项
  2. 02 / OBSERVE

    拆解参考与交互

    给出参考网址或截图，指出具体区块。检查布局、图片比例、文字层级，以及悬停前后、滚动起止和转场中间态。

    这一步交付参考点清单 · 动效触发与结束状态
  3. 03 / BUILD

    制作可运行首版

    先完成首屏、核心内容和主要交互。选择符合产品的高清素材，检查主体裁切；沿用合适的技术方案，提供能打开的预览。

    这一步交付可访问首版 · 真实素材 · 主要交互
  4. 04 / ITERATE

    按反馈局部迭代

    用“首屏、作品区、结尾”等稳定名称描述位置，说明改什么、保留什么。保留可恢复版本，只调整相关区域和必要依赖。

    这一步交付本轮改动摘要 · 更新后的预览
  5. 05 / VERIFY

    验证画面与功能

    在浏览器检查卡片四角、滚动中间态与终点、图片清晰度和层级。数量或尺寸变化后，核对滚动长度、导航、筛选和下载。

    这一步交付实际检查结果 · 已修问题 · 已知限制
  6. 06 / PUBLISH

    确认版本并发布

    明确要求后提交代码、同步仓库并部署 Pages。核对入口和资源路径，打开正式网址验收；仓库简介和 Website 单独设置。

    这一步交付提交记录 · 仓库链接 · 已验证的网址
一次反馈，写清三件事

位置：作品卡片区　 改动：间距缩小一半　 保留：图片、颜色和交互不变

05 / GOOD TO KNOW

使用前，了解这几件事。

适合哪些任务？+

适合从零制作产品单页、基于参考设计新页面、修改现有布局与文案、调试悬停与滚动动效，以及发布已经确认的版本。你可以从具体问题开始，不必每次重做完整流程。

安装后，会自动生成或发布网站吗？+

不会。它提供工作方法，仍然需要你在 Codex 中提出具体任务。需求不明确时会先澄清；公网发布、GitHub 上传等操作只在你明确要求的范围内执行。

必须使用 React 或有固定视觉风格吗？+

没有固定模板或强制技术栈。它优先沿用现有项目的合适方案；静态页面可以直接使用 HTML、CSS 和 JavaScript。颜色、素材、排版和设备范围由你的产品要求决定。

一轮结束时，我会拿到什么？+

应包括本轮具体改动、可点击的预览地址、实际检查结果和影响使用的限制。发布任务还应提供提交记录、仓库地址和已经验证的正式网址；代码上传成功与网站部署成功要分别确认。

网页里的示意可以直接运行 Skill 吗？+

这里是介绍与使用说明页面。真正执行任务，需要在能读取项目 Skill 的 Codex 环境中调用；浏览器中的复制、下载、标签切换和导航可以直接使用。
